# Repo Garbage Collector

Evidence first, deletion second. Every classification needs a trace: references, execution path, or test.

## Workflow

1. **Baseline (Phase 0).** Record root, date/time, Python version, OS, `git status --short`, tracked/untracked inventory (exclude `.git`, `.venv`, `__pycache__`, caches, vendored trees). Run existing tests/linters as configured; capture baseline, fix nothing.
2. **Evidence graph (Phase 1).** Build temp machine-readable manifest (JSON/SQLite/CSV under temp cleanup dir, removed before completion). Per file: path, type, size, mtime, tracked status, inferred purpose, inbound/outbound refs, importers/imports, CLI/config/scheduler/string refs, notebook refs, generated outputs/inputs, duplicate cluster, embedded claims (dates, counts, %, $, versions, absolute paths), test coverage, production-risk, recommended action + confidence. Exact hashing for dupes; heading/paragraph fingerprints for Markdown; AST-aware comparison for Python where practical. Classify: CANONICAL, GENERATED, HISTORICAL DECISION, ACTIVE PLAN, COMPLETED EVIDENCE, EXPERIMENT, REDUNDANT, STALE/WRONG, ORPHANED/UNKNOWN.
3. **Docs GC (Phase 2).** Build contradiction matrix (model identity, dates, ROI/xROI/EV/CLV/beat-rate/ECE/Brier/Sharpe/Sortino/DD/Calmar, counts, book universe, raw-vs-calibrated, gates, coverage, schedules, test counts, paths, commands). For each contradiction label: correct-for-different-population, stale-but-valid, irreproducible, deprecated-path, or wrong. Consolidate to smallest canonical set (merge into existing docs first). Delete Markdown only after migration when: duplicate, completed session report, stale generated numbers, superseded plan, deleted path, transcript/scratch/handoff with no durable decision, thin wrapper, or irreproducible with no rationale. Preserve consequential rationale as one-decision ADR (accepted/deprecated/superseded). Volatile numbers become generated artifact + command + provenance link, never hand-copied. Repair all links, TOCs, path refs; re-grep deleted names/headings.
4. **Backlog contract.** `docs/EXECUTION_BACKLOG.md` is the sole ledger: Current state, In progress (owner/agent, evidence, deps, acceptance), Next, Future, Deferred/Parking lot (reason + trigger), Verified blocked (evidence + unblock), Completed ledger (dated + artifact/test), Rejected/Superseded (reason/replacement). Each active item: stable ID, status, scope, why, deps, acceptance, validation command/artifact, evidence links, next action, out-of-scope.
5. **Python GC (Phase 3).** Map modules to package/entry/scheduled/ingest/feature/selection/grading/notify/plot/migration/experiment/test/obsolete. Per callable: importers, console/Modal/scheduler/config/notebook/test/dynamic refs, semantic duplicates, output consumers. Vulture/Ruff/IDE hints are candidates only. High-confidence cleanup: unused imports, unreachable blocks, obsolete shims, commented implementations, debug prints, dead flags/CLI branches. Consolidate devig/PnL/dedup/eligibility/close-match/calibration/risk/plot/date/load/alert logic into canonical modules. Notebooks import tested modules; no notebook-local production logic. Policy constants named + provenanced + tested. No absolute paths in reusable code (one env-aware resolver). Tiny modules merge only for cohesion (no utils dumping ground); splits only on domain boundaries. Core never imports notebooks/CLI/Modal/reports. Entry points import core, never reverse.
6. **Notebooks (Phase 4).** Per notebook: purpose, inputs/outputs, top-to-bottom reproducibility, stale outputs, hidden state, hard-coded dates/paths, copied metric/plot code, durable purpose (2025 explainer, 2026 sim, monitoring, publication, none). Extract reusable code to tested modules; notebook keeps narrative/orchestration/viz. Axes show as-of/cutoff; open/taken/close clocks consistent; replay/backtest/paper/fills labeled distinctly. Strip stale outputs unless intentional deliverable. Delete redundant after migration. Charts show population, range/as-of, n, units, denominator. CLV in pp when labeled pp. ROI/xROI never mix % and fractions. Risk states clock+unit. Partial months labeled. Missing closes reported, never silent-dropped. Selector n and close-eligible n never conflated.
7. **Static + deps (Phase 5).** Existing toolchain first. Sequence: Ruff report-only, formatter check, import sort/format after diff review, Vulture 100% then 90% manual (never auto-delete low-confidence), dep audit vs imports/metadata, configured type checker only (no new strict regime), import cycles, markdownlint after consolidation, local links then external with retries, notebook lint/clean execution where data permits, coverage as diagnostic. No whole-repo format churn mixed with semantic refactors.
8. **Artifacts (Phase 6).** Inventory CSV/JSON/Parquet/pickle/PDF/HTML/PNG/notebook outputs/logs/caches. Per artifact: generator command + code version, inputs + cutoff, canonical/reproducible/ephemeral/obsolete, secrets/paths/topics, source-control fit, doc links, duplicate snapshots. Never delete irreplaceable raw/model artifacts for size. Delete reproducible stale outputs with canonical tested generator. One declared output location; update refs/tests. Secrets audit: keys, tokens, webhooks, ntfy, paths, creds in notebooks/outputs. Never print secrets.
9. **Metrics + populations (Phase 7).** Funnel per headline: raw → eligible → policy → take-gate → deduped → staked → settled-non-void → valid-close → same-book-eligible → final metric. Report adds/removals per stage with reason. Assert canonical ticket-key uniqueness. Group/month splits sum to headline. Recompute PnL via canonical settlement. Recompute ROI/xROI/CLV/beat/win/DD/Sharpe/Sortino/Calmar from declared population or document denominator deltas. Never hard-code a sample count. Reconcile each count by artifact, code path, as-of, season/range, selector version, gates, books, line/side, staked/settled/void, dedup key, close coverage, replay-vs-live, policy-vs-opportunity-vs-ticket. Mismatch means different populations until proven. Name them explicitly. See `references/metric-invariants.md`.
10. **Execute in batches (Phase 8).** Order: docs, Markdown deletes + link repair, Python consolidation, dead-code/script removal, notebooks, artifacts/paths/configs, narrow lint/format, full validation. After each batch: focused tests, `git diff --stat` + targeted diffs, deleted-name search, entry-point orphan check, backlog update. Retain-but-flag anything unclassifiable with exact evidence needed.
11. **Verify (Phase 9).** Independent verifier (did not author changes): manifest diff, every deletion/move, migration-once check, broken-ref search, full tests, lint/format/type, entry-point validation without deploy, notebook top-to-bottom to temp copies, population reconciliation, secrets check, no-remote confirmation, pre-existing-change preservation, honest residual risk. See `references/verification-checklist.md`.

## Guardrails

- Read-only git: `status`, `diff`, `ls-files`, `log`, `grep`. No commit/push/pull/fetch/reset/checkout/rebase/merge/amend/stash/clean/tag/remote mutation. Tracked files may be edited/moved/deleted locally; leave uncommitted.
- Production jobs may hide behind Modal decorators, cron, CLI strings, magics, configs, dynamic imports, subprocess, shell, external automation. No delete on zero-import alone.
- GitHub/remotes untouched. Record initial tree; preserve pre-existing user changes.
- Prefer Polars. Never `git push`.

## Acceptance

Every Markdown/Python/notebook classified. Redundant/stale Markdown deleted post-migration. Canonical docs contradiction-free. Backlog sole ledger with all eight sections. Volatile numbers generated, not copied. Every headline has provenance/as-of/population/denominator. Populations reconciled, not papered. Entry points/Modal/graders/ntfy intact and testable without deploy. Duplicate metric/selection/settlement/devig/dedup/close/risk/plot logic reduced to adapters. Notebooks run in order or document external-data blocker. Dead-code evidence stronger than one analyzer. Tests ≥ baseline, no new failures. Links resolve. No remote mutation. Fewer sources of truth.
