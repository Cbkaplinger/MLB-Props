# PRD (PROPOSED 2026-10-21): Research delivery readiness

**Status:** Proposed.
**Planning horizon:** End of 2026, consistent with the previously recorded
scope deadline; that date should be reconfirmed in the canonical plan.

## Product objective

Deliver an auditable research-to-decision system in which an authorized user
can:

- Identify which model, data, contract, and policy produced an output.
- Reproduce an accepted result through the permitted data-access route.
- Distinguish implementation validity, predictive performance, and market
  usefulness.
- Detect stale or invalid inputs before treating outputs as actionable.
- Understand current limitations and promotion blockers.

## Non-goals

- No claim of institutional parity from repository size or documentation
  volume.
- No automatic promotion from offline predictive improvement.
- No new prop-market expansion on the current critical path.
- No speculative orchestration platform.
- No retrospective rewriting of frozen research.
- No additional paid-data purchase without a specific information-value case.

## Requirements and acceptance

| ID | Requirement | Acceptance evidence |
|---|---|---|
| R1 | Coherent agent responsibilities | Published governance revision; acknowledgments from all active agents |
| R2 | Safe integrated publication | Exact-head test receipt; no unresolved consumer compatibility failure |
| R3 | Executable experiment contract | Synthetic end-to-end success and negative tests for required invariants |
| R4 | Reproducible accepted result | Clean-environment reproduction with verified inputs and declared tolerance |
| R5 | Traceable data boundaries | Priority producer/consumer edges identify grain, keys, time semantics, missingness, provenance, and validation |
| R6 | Evidence-layer separation | PA, count/distribution, market, and decision claims remain separately identifiable |
| R7 | Operational failure visibility | Demonstrated handling of the selected stale, missing, duplicate, or invalid-input scenarios |
| R8 | Controlled research progression | Each next experiment has a hypothesis, expected information value, practical threshold, and stop condition |
| R9 | Navigable documentation | Canonical entry points resolve; historical and proposed material is labeled |
| R10 | Honest delivery state | Reports distinguish local, committed, published, reviewed, accepted, and merged |

## Milestone sequence

These are **proposed planning checkpoints**, not promises that scientific
results will be favorable.

| Target | Milestone | Exit condition |
|---|---|---|
| October 23 | Governance closure | One coherent published revision; agent acknowledgments |
| October 30 | M0 implementation gate | Exact-head independent check; all registered required outputs accounted for; execution authorization resolved separately |
| November 13 | Reproduction baseline | One accepted result reproducible through the documented environment/data route |
| November 27 | Research decision | Continue, stop, or redirect based on registered evidence - not sunk cost |
| December 11 | Operational evidence | Selected replay/shadow and failure-handling evidence assembled |
| December 18 | Scope freeze | Only critical correctness, reproducibility, and delivery fixes enter |
| December 31 | Release/readiness package | Evidence-backed capabilities, limitations, operating instructions, and unresolved blockers published |

If appropriate live opportunities are unavailable during this window, label
replay evidence as retrospective. Do not manufacture a
prospective-validation claim to meet a calendar deadline.

## Delivery measures

Measure: time from ready checkpoint to independent verdict; rework caused by
integration or contract mismatch; number of unresolved critical correctness
findings; reproduction success; required-artifact completeness; accepted
milestones per elapsed week; token or monetary cost per accepted milestone,
when available. Do not use commit count, documentation count, or lines of
code as success metrics.
