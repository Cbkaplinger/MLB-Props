# Strikeout-EDA

Exploratory analysis for the pregame pitcher strikeout-rate model.

## Folder naming convention

Each modeled statistic gets its own `<Statistic>-EDA` folder under its model
directory, e.g.:

- `Models/Strikeout-Model/Strikeout-EDA/`  (this one)
- `Models/Walk-Model/Walk-EDA/`
- `Models/Hit-Model/Hit-EDA/`
- `Models/Out-Model/Out-EDA/`

Keep this convention for walks, hits, and outs as those models are built.

## Contents

- `strikeout-eda.ipynb` - target distribution, correlations, skew/null audits,
  physics-vs-K scatter, stat stabilization curves, and a per-stat reliability
  table (split-half, ICC, year-over-year, SEM, regression slope, feature tiers).
- `stabilization.ipynb` - denominator-aware audit companion for candidate
  rolling windows.
- `run_stabilization.py` - reusable overall pitcher/batter stabilization run.
- `run_pitch_type_stabilization.py` - denominator-aware pitch-type
  stabilization run.
- `run_batter_discipline_stabilization.py` - focused stabilization for
  Z-Swing%, Swing%, Z-Contact%, and BB%.
- `run_batter_quality_stabilization.py` - focused stabilization for expected
  stats, contact quality, batted-ball shape, and batter run value.
- `feature_ablation.py` - protected feature-family screen on 2023-2024
  development folds.
- `window_ablation.py` - nearby-window redundancy screen on the same
  development folds.
- `targeted_window_ablation.py` - Phase 3 nested rerun of only the predeclared
  stabilization-gap candidates.
- `batter_discipline_ablation.py` - one-configuration nested family test using
  stabilization-nominated batter windows.
- `batter_quality_ablation.py` - capped nested comparison of flat,
  batting-order weighted, and weighted-plus-dispersion lineup representations.
- `Graphs/` - figures regenerated by running the notebook (written next to the
  notebook via `__vsc_ipynb_file__`, so renaming the folder never breaks paths).

## Running

From the repo root, with the project venv
(`pip install -e ".[research,dev]"`), open the
notebook and select the project environment. It reads the canonical Level 1
artifact at `Python.config.PITCHER_GAMES_PATH`. Run
`python -m Python.pipeline.games` first.

## Where the logic lives

Reusable reliability/stabilization functions were extracted to
`src/Python/reliability.py` (unit-tested in `tests/test_reliability.py`) so
feature-selection code can call the same routines the EDA uses:

- `stabilization_curve(...)` - split-half reliability vs window size, all stats at once.
- `reliability_table(...)` - split-half + Spearman + YoY + SEM + slope + tier per stat.
- `stabilization_by_denominator(...)` - pitch/zone/swing/PA-denominated curves
  used to choose candidate rolling windows.

Generated stabilization and feature-screen outputs are under
`artifacts/stabilization/` and `artifacts/feature_research/`. The completed
Phase 3 study did not change the global rolling constants. It supports
`rv_per_100_P25` only as a LightGBM-specific proposal; BABIP, arm angle, Ridge
run value, and unstudied physics/usage windows remain provisional. The added
batter-discipline family improved both LightGBM outer folds but remains
research-only until registry freeze.

The broader batter quality screen retained only ten lower-CI reliable metrics.
Weighted mean plus dispersion improved both LightGBM outer folds but worsened
Ridge MAE in both, so all 315 expanded candidates remain research-only.

> **Data note:** the pipeline retains the 2023-2025 regular seasons, while
> model fitting and feature research use only 2023-2024. The target deployment
> is 2026 projections (see `Python.config.PIPELINE_SEASONS`,
> `TRAIN_SEASONS`, and `PROJECTION_SEASON`).
>
> **Leakage note:** `PA`, `K`, and other same-game outcomes appear here only for
> analysis. They must never become pregame model features.
